## 三、⚠️ 两个必须先解决的问题

### 问题 1：三个工具页目前都是英文界面

小红书用户的体验链路是：**中文笔记 → 英文页面**。落地页写着 "Drop your HEIC files here"，语言断裂会显著拉高跳出率。

**三个选择：**

- **A（推荐）** 加中文版页面。共用引擎已支持多语言，复制一个 `zh/` 子目录或做语言切换即可，工作量不大。
- **B** 中文笔记里提前说明「界面是英文的，但只有几个单词，拖进去就能用」，把预期说在前面。文中已经预留了这句话，是当前最省事的做法。
- **C** 小红书这一路先只做「认知 / 科普」内容（如 avif 第 5 篇、webp 第 3 篇），不带转化目标，先养粉。

### 问题 2：海外主机的中国大陆可访问性

站点是给 Vercel / Cloudflare Pages 这类平台设计的，**国内访问通常不稳定**——尤其 `*.vercel.app` 和 `*.pages.dev` 这两个默认域名，大概率打不开或极慢。

**小红书流量是纯国内流量，这个问题会直接决定转化率。**

**三个选择：**

- **A** 买一个在国内解析速度正常的独立域名（.com 即可），指向 Cloudflare 并开启中国大陆优化节点。最省事，不需要备案，但速度一般。
- **B** 国内服务器 + **ICP 备案**。速度最好，能挂国内广告联盟，但备案需要时间和资质。
- **C** **海外流量和国内流量分开承载**：海外走 Vercel（英文内容 + AdSense），国内走备案站（中文内容 + 国内广告）。这是最正规也最长期的做法。

**在选好之前，先发英文那 15 篇**（Reddit / X / Quora / Shorts），不要急着把小红书流量引到一个打不开的站上。

## 四、部署前必改

把占位域名 `example.com` 换成真实域名。先看哪些文件涉及：

```bash
grep -rl "example\.com" . --include="*.html" --include="*.xml" --include="*.txt" --include="*.md"
```

涉及三处：

1. **4 个 HTML 页面** —— canonical / og / ld+json 结构化数据
2. **`sitemap.xml` + `robots.txt`**
3. **30 篇文章的链接字段**（每篇开头的 `**Link:**` 那一行）

批量替换（确认过再执行）：

```bash
grep -rl "example\.com" . --include="*.html" --include="*.xml" --include="*.txt" --include="*.md" \
  | xargs sed -i 's/example\.com/你的域名.com/g'
```

## 五、平台合规要点

| 平台 | 链接放哪 | 关键禁忌 |
|---|---|---|
| **Reddit** | 自己发的第一条评论 | 正文带链接 = 广告，直接删帖。**必须披露「工具是我做的」**，被扒出来比披露更惨 |
| **X / Twitter** | 最后一条推文 | 首条带链接会压流量。别在回复里补链接，会被判 link-bait |
| **Quora** | 正文末尾，注明 disclosure | 光贴链接会被折叠成垃圾内容。答案必须不靠链接也完整 |
| **YouTube Shorts** | 置顶评论 | 简介里的链接经常点不动，置顶评论更可靠 |
| **Hacker News** | 正文 | **任何形式的求赞都会被检测**。不要@人、不要拉票 |
| **小红书** | ❌ 正文不能放 | 外链是限流第一触发点。用**主页简介**承载，评论区问就**私信回** |

**小红书三条铁律：**
1. 正文、评论区都不出现域名
2. 首图不做成「工具推荐」的样子，要做成「信息 / 经历」的样子
3. 私信回复自动化风险高，手动回更安全

## 七、每条内容都基于已实测的数据

文案里所有数字都来自真机实测，不是估算：

| 数据 | 来源 |
|---|---|
| JPG q85 比 HEIC 大 68%、q70 大 16% | 1440×960 iPhone 照片，286.7 KB |
| Match original size 落在 q61 → 283.2 KB（−1%） | 同一张图 |
| WebP → PNG 大 746% / 1121% / 134% | 1600×1068 与两张小图 |
| WebP → JPG q70 小 39%（178.5 KB） | 同一张 294.6 KB 源图 |
| avif → JPG q70 大 3%、q95 大 163% | 168.3 KB avif 源图 |
| 转换期间外发 0 字节 | 页面内置网络计数器，真实浏览器实测 |

**好处有两个**：读者质疑时你有据可查；以及这些数字本身就是差异化——竞品页面几乎都不公布。

## 八、_dev/ 说明

`_dev/` 是不参与部署的校验工具，已改成自定位（不依赖任何固定路径）：

```bash
cd _dev
node verify-cluster.mjs          # 三页 124 项端到端校验，真实 Chrome + 字节级断言
node probe-sizes.mjs             # 测量各质量档 / 格式的真实输出体积
node gen-fixture.mjs             # 生成带透明通道的 WebP 测试样本
node shot-top.mjs                # 截取各页顶部区域
```

依赖 `playwright-core`。脚本会在本地 `_dev/`、环境变量 `PW_ROOT`、以及默认路径依次查找；都没有就提示安装方式。

**加新工具页时**：先跑 `probe-sizes.mjs` 量出真实体积，再写页面文案——页面上公布的每个数字都应该是测出来的。

> 部署时记得把 `_dev/` 排除，或者在构建配置里忽略它。
